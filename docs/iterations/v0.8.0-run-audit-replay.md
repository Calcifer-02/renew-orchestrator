# v0.8.0 — Token Audit, Timeline & Replay

## Зачем нужен audit

Audit позволяет убедиться, что состояние системы (refactor-plan.json) консистентно с
историей событий (events.ndjson). Без него можно незаметно получить расхождение между
реальным положением токена и тем, что показывает журнал.

## Зачем нужен replay

Replay восстанавливает ожидаемый маркинг из событий transition_fired и сравнивает с
фактическим. Если есть расхождение — выдаёт предупреждение. Это дешёвая форма
верификации без хранения полного снапшота.

## Как читать Token Timeline

Timeline — вертикальный список событий для конкретного токена, отсортированный по
времени. Каждое событие содержит:

- **ts** — метка времени (ISO 8601)
- **type** — тип события
- **summary** — читаемое описание на русском
- **job_id** — если событие связано с заданием

Типы событий:

| type              | описание                                 |
|-------------------|------------------------------------------|
| task_created      | Токен создан в BACKLOG                   |
| transition_fired  | Петри-переход выполнен                   |
| job_created       | Создано задание агента                   |
| job_completed     | Задание завершено, переход выполнен      |
| job_failed        | Задание провалено                        |
| budget_spent      | Бюджет списан                            |
| budget_blocked    | Действие заблокировано нехваткой бюджета |
| smoke_cleanup     | Токен удалён (smoke cleanup)             |

## Как запускать report

```bash
python bridge/renew_bridge.py --project-dir PATH report TASK_ID
```

Выводит markdown-like отчёт с секциями:
- Метаданные токена (место, статус, попытки)
- Timeline событий
- Jobs (статус каждого задания)
- Transitions (список переходов)
- Human decisions (если были)
- Economy (если есть бюджетные события)
- Consistency (OK или список предупреждений)

## Как запускать replay dry-run

```bash
python bridge/renew_bridge.py --project-dir PATH replay --dry-run
```

Возвращает JSON:

```json
{
  "ok": true,
  "warnings": [],
  "reconstructed_marking": {"TASK-001": "DONE"},
  "actual_marking":        {"TASK-001": "DONE"},
  "total": 42,
  "by_type": {"task_created": 1, "transition_fired": 6, ...}
}
```

`ok: true` означает полную консистентность. Предупреждения бывают:

- `missing event_id` — старые события без UUID
- `transition_fired for unknown task` — событие без task_created
- `job closed without job_created` — закрытие несуществующего job
- `budget_spent without job_completed` — списание до завершения задания
- `place mismatch` — место в refactor-plan не совпадает с events
- `task in actual marking has no task_created event` — импортированный/битый токен

## Как чистить smoke tokens

```bash
python bridge/renew_bridge.py --project-dir PATH cleanup-smoke --prefix UI-
python bridge/renew_bridge.py --project-dir PATH cleanup-smoke --prefix SMOKE-
python bridge/renew_bridge.py --project-dir PATH cleanup-smoke --prefix E2E-
```

Или через API:

```http
POST /api/debug/cleanup-smoke
{"prefix": "UI-"}
```

Поведение:
- Удаляет задачи с prefix из refactor-plan.json
- Удаляет связанные jobs из agent_jobs.json
- Освобождает resource locks
- Записывает событие smoke_cleanup в events.ndjson
- Пересобирает current_marking.md
- **Не трогает** events.ndjson

## API endpoints (v0.8.0)

| Method | Path                              | Описание                        |
|--------|-----------------------------------|---------------------------------|
| GET    | `/api/tokens/{task_id}/timeline`  | История конкретного токена      |
| GET    | `/api/audit/consistency`          | Проверка консистентности        |
| GET    | `/api/audit/replay`               | То же (алиас)                   |
| POST   | `/api/debug/cleanup-smoke`        | Удаление smoke-токенов          |

## Frontend

В инспекторе токена появились вкладки **Инспектор** и **История**.
«История» загружает `/api/tokens/{task_id}/timeline` и показывает вертикальный timeline.

Панель **Аудит** в сайдбаре обновляется раз в 30 секунд и показывает:
- Статус консистентности (OK / N предупреждений)
- Кол-во событий, задач, типов
- Первые 5 предупреждений (если есть)

## Ограничения текущей реализации

1. Replay не восстанавливает состояние jobs — только место токена.
2. smoke_cleanup удаляет задачи из обоих файлов, но не из trace.json
   (trace.json — историческое дерево, не перезаписывается).
3. Timeline не поддерживает пагинацию — при большом числе событий
   загружается весь список.
4. Audit panel не подписывается на SSE — только polling раз в 30 с.
